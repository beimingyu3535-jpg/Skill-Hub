## 核对后保留的边界与资料冲突

| 项目 | 指南处理 |
|---|---|
| `formSdk` 闭包实例的最低基线 | 说明与开发必看主体写 250101；常见问题和开发必看一处又写 241201。指南按 250101 作为稳妥门槛，较早环境须实际检查。 |
| 明细新增时使用末行数据 | 原文 5.17 列 `setDetailAddDefLast`，示例却调用 `setDetailAddUseCopy`；5.6 又单独列后者。两种 API 均保留，前者行为在目标环境核对。 |
| `getFieldCom`、字段赋值及明细属性的示例笔误 | 在[排查文档](ref-troubleshooting.md)列出，专题示例采用修正后的调用形状。 |
| 附件 `data`、插件具体方法、外部查询接口 | JSSDK 资料未给出完整提供方契约。指南说明如何接入和从现有数据读取，但不编造文件对象、插件方法或接口。 |
| 审批节点提交拦截 | 表单 JSSDK `OPER_SAVE` 只覆盖表单数据保存；流程提交属于流程 SDK，本目录不宣称覆盖。 |
| 页面组件 props 全局复写 | 原案例使用 `regOvProps`，是 ecode 层功能；与布局源码的字段局部渲染分别路由。 |

资料中所提工作流程 SDK、EB SDK、UI 组件和具体插件文档并不属于这 91 篇 JSSDK 资料；本目录只描述已给出的跨界入口，不臆造其完整方法。涉及这些外部契约时读取对应专题或说明尚缺契约。
