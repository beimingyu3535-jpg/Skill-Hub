# 搭建计划模板（按依赖与功能批次执行）

使用本模板生成项目 `plan.md` 时，先读[规划能力地图](map.md)识别资源、配置和依赖；需要明确具体规则或能力边界时读对应专题指南，再填写实际涉及的条目。执行某项前仍须读取该项指南。

规划阶段全部保持 `[ ]`。第一阶段先完成全部表单的字段、明细和布局，再以**功能项为外层、所有适用表单/视图为内层**组织配置：例如先完成所有表单的关联浏览数据范围，再处理所有表单的公式；视图也按显示列、搜索、排序等功能逐批覆盖。每进入一个功能项先读对应指南，确认方法、参数和边界；同一连续批次已读过的无需重复读取。每个对象及独立规则分别列项、核对、回填和销号；暂不能完成的保留 `[ ]` 并注明原因、已完成部分及所需条件，继续处理其他项目，不因步骤繁琐而省略。整个功能批次的覆盖对象处理完后进入下一批次，真实依赖优先于批次顺序。每段完成后停下让用户确认，确认后进入下一段。仅单步修改或查询不套用三段流程。

## plan.md 参考骨架

复制本节到项目工作区的 `plan.md`，只保留需求涉及的资源和功能；每条业务要求都有明确归属、来源、依赖和可观察结果。同类功能可连续执行，但不能把多条独立要求合成一个销号项。

```md

> `[ ]` 为未完成；写入且按该项风险完成必要核验后，才改 `[x]` 并填写真实 ID 或结果。尚待后续资源的项保留 `[ ]` 并写明依赖。

- 明确还原图片/XLSX源样式时，另记录源哈希、LayoutSpec、已有字段绑定、编译产物和独立回读结果。字段创建完成与布局还原通过分别勾选；未匹配、未支持项不能合并销号。相关指南为 `form/guide-form-layout-source.md`，精确保存晚于字段补写和归组重排。
```

## 使用边界

- 资源清单负责保存“建什么、复用什么、谁依赖谁”，功能批次负责“具体配置什么”；两处用资源名称或实际 ID 对应，不重复创建同一资源。
- 字段和布局蓝图仍逐表保存，防止按功能批次执行时遗失字段顺序、分组和表格空间结构。
- 功能批次只规定同类操作的优先处理顺序。出现跨表循环、流程 ID、目标页面等依赖时，按真实依赖先建立资源，再回到相应条目完成配置。
- 最小核验与业务风险相称；仅在用户要求时进行实际环境测试。计划销号仍以配置完成及必要的结果核对为准。
