# E10 智能搭建规划能力地图

本页用于把完整实施方案转成项目 `plan.md`：识别资源归属、配置项、依赖、待确认问题与关键验收结果。规划时先读本页和[计划模板](guide-plan-template.md)，执行某项配置前再读取对应专题指南。本页不提供命令参数或字段码表。

## 使用方法与状态

1. 逐段阅读正文、表格和图片，将每条业务要求映射到资源与配置项，记录原文来源、所属应用/表单/视图/流程、前置依赖及可观察结果。已有资源先只读盘点，再决定复用、修改或新建。
2. 需求含完整布局样表时，按[布局规划](../form/guide-form-layout-planning.md)保留标题、分组、同排、空白与字段顺序，并同时写入字段清单和布局蓝图。每张表单创建前确认 FLOW 或 EXCEL。
3. 规划状态区分：**待业务确认**（语义或取值有歧义）、**待环境核查**（资源、权限或环境行为未证实）、**需其他方式补充**（现有 CLI 只能完成一部分）、**已确认无法实现**（核实无可行路径）。只有最后一种写入 plan 的“无法实现的项”，原需求项保持未完成。
4. 按资源依赖组织 plan；关键配置写明读回点和最小业务验收点。接口保存、配置读回与页面实际生效是不同层次，按风险选择必要的检查。

## 平台概念

- **Ecode** — 存放和运行代码的平台；自定义页面在这里编码、构建、运行。
- **Ebuilder 应用** — 独立概念，包含表单、流程等资源（与 Ecode 项目不同）。
- **默认台账与菜单入口是两件事** — 表单创建后会生成默认台账/列表视图，但 `form create` 默认不加应用菜单；需要入口时用 `--menu`，或建表后 `menu add-table`。默认台账已存在不等于菜单入口已存在。
- 只有图表仪表盘、跨表单聚合视图、特殊交互流程、对外公开页面等场景才需要自定义页面。
- 所有系统交互命令均通过 `e10-cli` 执行（已全局 link）。auth 文件自动查找，也可 `--auth <path>` 指定。
- 当前登录用户的 userId 是固定变量 `TEAMS.currentUser.id`，前端代码里可以直接使用。

| 原生工作流程 | 流程中心或明确要求原生表单的审批 | 写自建/绑定表单、固定/自由模式和 formId | 与 EB 资源 ID 分开；验收流程与绑定表单 | [流程](../workflow/guide-workflow.md) |
| 公文流程 | 原生工作流程中的公文业务 | 写公文类型及专属设置要求 | 按当前支持状态逐项核对设置 | [公文](../workflow/guide-workflow-odoc.md) |
| 权责表 | 按分支场景矩阵维护或复用审批路径 | 写随流程新建/独立复用、节点路径和变量映射 | 验收场景条件、路径与映射 | [权责表](../workflow/guide-workflow-auth-resp.md) |
| 动作流 | 跨表写入或事件自动化 | 写触发点、源/目标字段及记录定位 | 验收动作绑定与目标记录变化 | [动作流](../workflow/guide-workflow-action.md) |
| HRM 矩阵 | 按组织条件决定流程操作者 | 写条件、输出列、数据行及引用节点 | 结构和数据都需有效；验收命中结果 | [矩阵](../hrm/guide-matrix.md) |

| 配置式页面 | 用设计器组件搭建页面 | 写数据源、组件、布局和 PC/MOBILE 要求 | 验收两端布局与数据绑定 | [设计器](../ebuilder-designer/guide-designer.md) |
| 定制页面 | 实现标准配置之外的交互 | 写目标页面、作用范围、发布与入口 | 验收实际加载和业务交互 | [页面编码](../coding/guide-page-code.md) |
| ESB 系统接口 | 从接口文档创建对外接口定义 | 写系统池、接口清单和文档来源 | 区分接口定义与动作流 HTTP 调用；验收创建结果 | [接口导入](../esb-interface/guide-import.md) |
| 组织数据 | 维护部门、人员等基础数据 | 写机构归属、人员来源和导入范围 | 批量导入先预检；验收数据和归属 | [组织](../hrm/guide-org-employee.md) |

## 二、功能配置地图：资源建成后还要做什么

下表用于识别应写入 plan 的配置，不表示每个项目都要启用。具体取值和命令由专题指南确定。

### 表单、字段与布局

| 选项与默认值 | 限定可选值或预置新记录内容 | 字段；写选项、默认值及触发时机 | 选项模板与字段内选项分别记录；验收新建页面 | [字段码表](../form/ref-form-fields.md) |
| 字段多语言 | 同一字段显示中英文名称 | 字段；写中文、英文及目标 fieldId | 建字段后配置；验收两种语言读回 | [创建表单](../form/guide-create-form.md) |
| 字段显示属性 | 控制必填、只读、隐藏及独占一行 | 布局；逐字段写目标状态 | 字段定义与布局呈现分别核对 | [布局规划](../form/guide-form-layout-planning.md) |

| 配置式页面 | 使用设计器组件组织展示与交互 | 写数据源、组件、布局和终端 | 验收 PC/MOBILE 布局与数据 | [设计器](../ebuilder-designer/guide-designer.md) |
| 定制页面 | 实现标准配置之外的交互 | 写目标范围、页面代码和发布入口 | 验收实际加载与交互 | [页面编码](../coding/guide-page-code.md)、[导出发布](../coding/guide-page-export.md) |

## 三、易混能力选择

| 需求要改变的结果 | 规划选择 |
|---|---|
| 有一张持久化的业务表 | EB 表单；以已有来源组合展示时评估虚拟表 |
| 新建业务审批 | 默认 EB 表单与应用内流程；明确要求原生工作流程或流程中心时选择原生路径；公文再加专属设置 |
| 审批路线由多组条件决定 | 普通流程用节点与出口条件；要求矩阵式分支维护或复用时规划权责表 |
| 选择其他业务对象并带出字段 | 对应原生关联字段负责选择；字段带出/函数联动负责赋值；关联页签负责侧面展示相关记录 |
| 控制记录可见范围 | 表单/视图权限；列表数据条件负责视图展示筛选 |
| 展示表单数据给用户 | 默认台账或新增视图；菜单负责导航入口；报表用于多源统计与专门报表布局 |
| 点击按钮打开关联任务或发起流程 | 视图按钮或表单按钮，逐项写目标、当前行过滤与预填映射 |
| 复杂自动写入其他表 | 动作流，写清触发、字段映射及目标记录定位；单纯本表计算选公式/联动 |
| 标准配置无法表达的页面交互 | 明确目标范围后规划配置式页面或定制页面，并单列发布和交互验收 |
| 当前表单布局中的字段、明细或交互需用 JS 实现 | 规划布局源码或表单级 ecode：写目标表单、布局/终端、触发事件、字段 Key、效果和运行检查；按[代码块指南](../code-block/guide-code-block.md)选 CLI 写入入口和对应 JSSDK 方法 |

## 四、常见依赖与计划顺序

这些是依赖关系，不替代 [计划模板](guide-plan-template.md)的三段执行规则。已有且符合要求的资源可复用，按真实 ID 解除依赖。

```text
环境/机构 → 主应用与角色 → 表单/字段/明细 → 布局与默认台账 → 视图/权限/按钮
数据源与目标表单 → 关联字段/虚拟表 → 联动、筛选与关联页签
表单字段 → 流程/节点/连线 → 操作者/条件/节点配置 → 动作流
独立权责表变量 + 流程表单字段 → 变量映射；随流程新建权责表则直接使用表单字段
数据集与精确字段 → 报表设计 → 查询与共享
目标视图/流程/页面 → 菜单绑定 → 页面入口验收
```

流程创建后产生的 ID 若被表单或视图按钮依赖，先在 plan 标明依赖，再在流程段回填。跨表循环引用可先建立独立骨架，待两侧资源存在后补关联。流程拓扑调整后按[流程指南](../workflow/guide-workflow.md)处理布局。

## 五、规划预检

| 检查点 | 在 plan 中如何处理 |
|---|---|
| 业务含义不清 | 写出不同解释会改变的字段、权限或路由，提出具体确认问题 |
| 文档内容冲突 | 标出原文位置和受影响配置，待用户确认后定稿 |
| 资源新建/复用不明 | 只读盘点同名资源、归属和 ID；不能唯一确定时标“待环境核查”或请用户选择 |
| 布局或字段来源缺失 | 确认 FLOW/EXCEL、样表结构、目标字段和关联来源；保留可确认内容 |
| 环境能力尚未核实 | 列最小查询/验证动作，保持“待环境核查”，不直接判为无法实现 |
| 仅能部分配置 | 分别列可完成部分与需页面/其他系统补充部分，注明责任和验收方式 |
| 已确认无法实现 | 原需求项保持 `[ ]`，在 plan 第 8 节记录原因、影响及待用户决定的处理 |
| 验收标准不足 | 给关键配置写读回字段与一个典型页面/业务结果，避免只凭保存成功销号 |

规划结果应能回答：要建或复用哪些资源、每条需求落在哪个配置项、依赖顺序是什么、哪些信息须确认、哪些需环境核查、哪些只能部分实现，以及如何判断关键结果生效。最终清单与逐项销号使用[计划模板](guide-plan-template.md)。
