# 数据源选用与多源父格（强制）

> **适用**：需求分析、配置生成、API 建表。 
> **目标**：少挂数据源、少配父格筛选、控制找表空耗。

---

## 〇、左父格默认优先（强制 · 单数据集）

> **事故对照**：同一需求文件生成的「供应商信息管理」`866766714447126529` 与「供应商-1」`1312703681350901760` 均为**单数据集**，却一个把字段左父格串成「逐列自定义链」，一个把明细列都自定义挂到分组列 —— 设计器里大量显示「自定义」，与常规「默认」不一致。

**原则**：无多数据集、且需求**未指定**特殊计算/交叉/合计挂靠时，**Field / 普通 Const** 左父格一律默认（`leftX=-1, leftY=-1` / `["default",0,0]`）。

> **例外（强制）**：**超链接 Const**（`pcHreflink` 含 `{L4}` 等）**不适用**「左父格默认」。上父格仍为 `-1`；左父格须指向占位依赖的数据格。见 `report-self-check-guide.md` §2.2。 
> **已有报表**：用户未点名时**禁止**批量改父格。

| 场景 | 左父格 | 说明 |
|------|--------|------|
| **单数据集**列表 / 简单分组 | **默认** | 引擎按相邻扩展自动解析；**禁止**为「看起来整齐」逐格写 custom |
| 单数据集但需求写明合计行挂某分组、交叉表行列挂靠、公式指定父格 | **自定义**（仅涉及的格） | 见 building-guide / formula-cell-api-guide |
| **多数据集**跨源关联 | 连续同源区**仅入口格**自定义 + 父格筛选 | 见 §二；其余默认 |

**硬约束**

1. 报表内有效 `dataSetId` 只有 **1 个**（忽略 `-1`）→ **新建/从需求生成时** Field 左父格用 default；**禁止**链式 `左父格=上一列`、也**禁止**无必要地把所有 List 列挂到同一 Group 列。
2. 同数据集 **禁止**配 `leftFilterField` / `subordination`（那是跨源用的）。
3. 只有用户/需求明确「按 XX 分组计算」「合计挂在 A3」「交叉维」时才对该格设自定义父格。
4. 需求分析列级表：单数据集时「父格」列填 **默认**，勿臆造自定义坐标。
5. **禁止擅自改已有报表父格**：用户仅强调「规则上默认即可」时，**只更新 Skill/新建逻辑**；**不得**对线上已有报表批量把自定义左/上父格改成 default，除非用户**明确要求修改该报表**。
6. **上父格**：无交叉/横向扩展需求时保持默认/无；勿给普通列表单元格（如 M4 链接文案）乱设上父格。

## 一、尽可能少用数据源（强制）

**原则**：主业务表上**已有**可展示字段时，**禁止**仅为「好看/完整」再挂关联表。

| 场景 | 正确做法 | 错误做法 |
|------|----------|----------|
| 考勤表已有用户 ID / 姓名 / 工号 | 直接绑考勤表字段 | 再关联人员表只为显示人员 |
| 人员表已有部门名称 / 部门 ID | 直接绑人员表部门字段 | 再关联部门表只为显示部门 |
| 合同表已有供应商名称 | 直接绑合同表字段 | 再挂供应商主数据表只为回显名称 |
| 需求明确要「主数据维度扩展」（如按部门树下钻、人员多属性）且主表无该字段 | 才允许加第二数据源 | — |

**判定顺序**

1. 先读主表 `fieldsAndOriginFields` / `form read`，列出需求列能否在**同一 sourceId** 上取到。
2. 能取到 → **只 add 这一张表**（或需求点名的最少表集合）。
3. 取不到且业务必须跨表关联 → 再加第二源，并走 §二 父格规则。

**禁止**：按「业务实体清单」机械每人/每部门/每组织各挂一张表；禁止未核对字段就先 `addDataset` 多张。

## 二、多数据源 · 连续区域父格筛选（强制）

> 跨数据集关联仍遵守 `cross-dataset-filter-guide.md`（fieldKey、`id=currentField` 等）。本节约束 **配多少次**。

### 2.1 规则

同一布局里，若**连续一片区域**（连续行或连续列）的字段**全部来自同一数据源 B**，且需挂到另一数据源 A 的父格下：

| 单元格 | 左/上父格 | subordination + leftFilterField（父格筛选） |
|--------|-----------|-----------------------------------------------|
| **该连续区域的第一个**字段（区域入口格） | 指向 **A 侧**父格字段（自定义父格） | **必须配置**（与 A 的关联键） |
| **同区域后续**字段 | **默认父格**（跟随入口格扩展链，通常 `"default"`） | **禁止**再逐格指定父格为 A，也**禁止**再配一套父格筛选 |

### 2.2 示意

```
A 区（数据源 A）… 末字段
B 区连续（数据源 B）：
 B1 左父格 → A.关联键字段 + 父格筛选（A.key = B.fk） ← 仅此格
 B2 父格默认
 B3 父格默认
 …
```

### 2.3 反例

- 对 B1、B2、B3 **每个**都设 `leftParent` 指向 A，并各写一遍 `leftFilterField` → 冗余、易错、预览异常风险高。
- 连续区域被公式列/常量列打断后仍当成「一整块」不配入口格筛选 → 关联失效。若区域被异源单元格打断，**每一段**各自的首字段仍须单独配入口筛选。

### 2.4 与需求分析表的填法

列级配置总表中：

- 连续同源区域：**仅入口列**「父格筛选」写关联；其余列父格筛选填 `-`，父格填 `default`（或文档约定的默认）。
- **关联键来源**（见 §2.5）：需求已写明 → 直接填；推断得到 → 父格筛选列标注「推断·待确认」，并在待确认项列出。

### 2.5 多表关联键：需求优先 · 推断须确认（强制）

> 报表挂 **≥2 个数据集** 且需跨源父格筛选时适用。配置写法仍见 `cross-dataset-filter-guide.md`。

#### 2.5.1 关联键如何确定

| 优先级 | 来源 | Agent 行为 |
|--------|------|------------|
| **1** | 需求/用户**明确**写出两表关联（如「销售单.客户ID = 客户.ID」「按供应商名称关联」） | **直接**按该对字段配入口格 `subordination` + `leftFilterField`；**不必**再问 |
| **2** | 需求**未写**关联字段 | 用两表字段元数据**检索匹配**（见下）→ 选出候选 → **必须提示用户确认** 后再落库；用户未回时可用置信度最高的一对**先配**，但交付时注明「推断关联·请确认」 |
| **3** | 无法推断或候选冲突 | **打断询问**关联关系；**禁止**瞎配；可先交单表/已确认部分，关联筛选标待补（非阻塞，见 `failure-cleanup-and-nonblocking-guide.md`） |

#### 2.5.2 字段值/元数据匹配（需求未写明时）

对父表 A、子表 B 的字段列表（优先 `fieldsAndOriginFields` / `e10-cli report join-suggest`）：

1. **显示名全等**（如双方都有「供应商名称」）→ 高置信 
2. **系统名/业务键同构**（同 `field_*` 后缀模式、`xxxId`↔`xxx`、外键命名含对方表名）→ 中高置信 
3. **名称近似**（去后缀「编号/名称/ID」后相同、一方「客户」一方「客户名称」）→ 中置信 
4. **多候选同分** → 全部列出，**禁止**静默任选一个不告知 

**禁止**：仅凭表名臆造 fieldKey；禁止用显示名当 `parentField`/`currentField`（必须三段式 fieldKey）。

#### 2.5.3 必须给用户的确认话术（推断时强制）

推断关联后，交付/询问中**至少**说明：

```
【关联待确认】表 A「…」与表 B「…」未在需求中写明关联字段。
已按字段匹配推断：A.{显示名/系统名} Equals B.{显示名/系统名}
请确认是否正确；若不正确请给出正确关联（A.字段 = B.字段）。
```

用户确认或纠正后，再改入口格筛选（定点改，见 `targeted-fix-guide.md`）。

#### 2.5.4 CLI（优先）

```bash
e10-cli report join-suggest --app-id <appId> --parent-source <sourceIdA> --child-source <sourceIdB>
# 或按表名：
e10-cli report join-suggest --app-id <appId> --parent-form "销售单" --child-form "销售明细"
```

输出候选对 + `needConfirm=true`；Agent **优先调 CLI**，勿手写比对脚本。
